## Project

"Orbit" — a Docusaurus 2 documentation site combined with a suite of standalone interactive React tools and browser games, deployed to Firebase Hosting (project `canvas-eye-416011`). Content docs live in `docs/`; interactive pages live in `src/pages/`.

## Commands

```bash
npm start              # dev server (docusaurus start)
npm run build           # production build -> /build
npm run serve            # serve the production build locally
npm run clear             # clear Docusaurus cache (fixes stale sidebar/build issues)
npm run sass               # watch-compile src/scss/style.scss -> src/css/style.module.css
```

There is no test suite or linter configured in `package.json`. There is no `server/` directory in this checkout — ignore any references to running a separate Node server.

Deploy (manual, only when asked):
```bash
npm run build
firebase deploy --only hosting
```

## Environment variables

`docusaurus.config.js` loads `.env.${NODE_ENV}` via `dotenv` and exposes values through `customFields` (accessed at runtime via `useDocusaurusContext().siteConfig.customFields`):
- `REACT_APP_N8N_API_URL` — N8N webhook used by `src/pages/rest-adapter.js`.
- `FIREBASE_*` — Firebase config, also duplicated in `src/config/firebase.js`. Note: `src/utils/gameChannel.js` (multiplayer games) does **not** use these — it fetches Firebase config at runtime from `/__/firebase/init.json`, which Firebase Hosting serves automatically, so no keys are needed for that path.

## Architecture

**Two content types coexist:**
- `docs/` — Markdown/MDX documentation (Angular, AOP, RabbitMQ, Redis, SQL, Swagger, Spring/Hibernate/PL-SQL, MultiExecPro, etc.). Sidebar is fully autogenerated from folder structure (`sidebars.js`, `{type: 'autogenerated', dirName: '.'}`) — adding a new doc folder/file is enough, no manual sidebar edits.
- `src/pages/*.js` — each file is a standalone routed React page (Docusaurus file-based routing), used for interactive tools and games rather than docs content. New tools/games are added here and then linked from the navbar (`docusaurus.config.js` → `themeConfig.navbar.items`), not from `sidebars.js`.

**Interactive tools** (`src/pages/`): `json-formatter.js`, `sql-formatter.js`, `jwt-decoder.js`, `regex-tester.js`, `data-converter.js`, `http-status-codes.js`, `spring-boot-annotations.js`, `apiDocumentationGenerator.js` (regex-parses Java Spring annotations like `@PostMapping`, `@PreAuthorize`, `@Operation` into HTML doc tables), `create-new-document.js` (Monaco-based live Markdown editor), `rest-adapter.js` (sends input to the N8N webhook and renders the JSON/text response).

**Browser games** (`src/pages/`): `tic-tac-toe.js`, `dots-and-boxes.js`, `eight-puzzle.js`, `number-guessing.js`, `trains.js`. Multiplayer games use `src/utils/gameChannel.js::connectGame(gameId, onMessage)` — a Firebase Realtime Database-backed replacement for a WebSocket connection (seat claiming via transaction, per-player "mailboxes" for message relay, `onDisconnect` cleanup). It returns `{ send(jsonStr), close() }` matching a WebSocket-like interface, so game logic doesn't need to know it isn't a raw socket. Requires the Realtime Database to be enabled in the Firebase console with rules under `games/$gameId` (see comment header in the file).

**Seasonal decorations**: `src/config/eventConfig.js` selects one "active event" component from `src/components/EventDecorations/events/` (Ramadan, EidAlFitr, EidAlAdha, NewYear, JordanIndependenceDay, StarField) by uncommenting an import and setting `activeEvent`. `EventDecorations/index.js` is generic and never needs editing — add new seasonal effects as new files in `events/` following an existing file as a template.

**Styling**: SCSS compiled to `src/css/style.module.css` via `npm run sass`, organized as `abstract/` (variables, mixins, functions), `base/` (typography, resets, animations), `components/`, `layout/`, `pages/` (per-page styles, e.g. `_createNewDocument.scss`). Global CSS entry for Docusaurus theming is `src/css/custom.css` (referenced in `docusaurus.config.js` `theme.customCss`).

**Code editors**: Monaco (`@monaco-editor/react`) is used for the Markdown editor; CodeMirror (`@uiw/react-codemirror` with Java/JS/SQL language packs) is used elsewhere for syntax-highlighted code display/editing.
